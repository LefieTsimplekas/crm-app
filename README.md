# Leads CRM

Εφαρμογή CRM για τα leads της έκθεσης. Τα δεδομένα αποθηκεύονται στο Supabase (PostgreSQL)· η εφαρμογή είναι μία στατική σελίδα (`index.html`) που φιλοξενείται στο GitHub Pages.

## Δομή
- `index.html` – όλη η εφαρμογή (οθόνες, φόρμες, λογική).
- `db/schema.sql` – οι πίνακες της βάσης και οι κανόνες πρόσβασης (χωρίς δεδομένα).
- `manifest.webmanifest`, `sw.js`, `icons/` – για την εγκατάσταση ως εφαρμογή.

## Λειτουργίες
- **Παρακολούθηση**: ανοιχτά leads ανά χρονιά/χειριστή, με κόκκινο / πορτοκαλί / πράσινο ανάλογα με τις ημέρες χωρίς επαφή, pipeline και επιλογή στηλών.
- **Νέο lead / νέα εταιρεία**, **Νέα ενέργεια / σχόλιο** (με ενημέρωση πορείας lead), **Νέα επαφή**, **Διαγραφή** (lead ή ολόκληρη εταιρεία), **Μετονομασία**.
- Καρτέλα εταιρείας με στοιχεία, επαφές, leads ανά χρονιά και ιστορικό ενεργειών.
- **Σύνοψη** ανά χρονιά με σύγκριση με την προηγούμενη, **Ρυθμίσεις** (λίστες επιλογών, νέος χειριστής, αλλαγή κωδικού).
- **Εξαγωγή σε Excel** για αντίγραφο ασφαλείας και **Εισαγωγή από Excel/CSV** με αντιστοίχιση στηλών και έλεγχο διπλών.
- Προειδοποίηση για εταιρείες που μοιάζουν με υπάρχουσες (π.χ. «Goodwe Hellas ΑΕ» → GOODWE).
- Εγκατάσταση ως εφαρμογή (PWA) σε υπολογιστή και κινητό.

## Ασφάλεια
Το κλειδί μέσα στο `index.html` είναι το *publishable* κλειδί του Supabase, που προορίζεται για δημόσιες σελίδες. Τα δεδομένα τα βλέπουν μόνο συνδεδεμένοι χρήστες (Row Level Security). Νέοι χρήστες προστίθενται από το Supabase → Authentication → Users → Add user.

## Νέα έκδοση (React) – φάκελος `web/`

Η νέα έκδοση χτίζεται δίπλα στην τωρινή και δημοσιεύεται στο `/crm-app/next/` με την **ίδια βάση**. Όταν ολοκληρωθεί, θα πάρει τη θέση της τωρινής.

- **Εργαλεία:** React 19 + TypeScript (strict) + Vite, Mantine 9 (UI και styling), Supabase JS, Vitest, ESLint, Prettier.
- **Δομή:**
  - `src/domain/` – κανόνες και υπολογισμοί χωρίς UI (κατάσταση leads, pipeline, φίλτρα) με tests (`*.test.ts`)
  - `src/data/` – σύνδεση με το Supabase, δεδομένα στη μνήμη με ζωντανή ενημέρωση, προσωπικές ρυθμίσεις
  - `src/components/` – κοινά components (πίνακας με ταξινόμηση/πλάτος, επιλογή στηλών, καταστάσεις φόρτωσης/σφάλματος/κενού)
  - `src/pages/` – οθόνες
  - `src/theme.ts` – design tokens (χρώματα, γραμματοσειρές, αποστάσεις, στρογγυλοποιήσεις)
- **Εντολές** (μέσα στο `web/`): `npm ci`, `npm run dev`, `npm run typecheck`, `npm run lint`, `npm run format`, `npm test`, `npm run build`.
- **Δημοσίευση:** `.github/workflows/pages.yml` – σε κάθε push στο `main` τρέχουν έλεγχοι και tests, χτίζεται η νέα έκδοση και δημοσιεύονται και οι δύο. Απαιτεί Settings → Pages → Source = «GitHub Actions».

### Κανόνες React και UI
- TypeScript με strict mode.
- Μία βασική UI βιβλιοθήκη (Mantine) και ένα σύστημα styling σε όλο το project.
- Κοινά design tokens για χρώματα, γραμματοσειρές, αποστάσεις και στρογγυλοποιήσεις (`src/theme.ts`).
- Μικρά components με σαφή σκοπό· επαναχρησιμοποιήσιμα όταν υπάρχει πραγματική επανάληψη.
- Όχι απευθείας αλλαγές σε props ή state· μόνο με τις συναρτήσεις ενημέρωσης του React.
- Hooks μόνο στην κορυφή ενός component ή custom Hook· όχι παρενέργειες κατά το render.
- Σε λίστες, σταθερό και μοναδικό `key` από τα δεδομένα.
- Σημασιολογικά HTML στοιχεία (`button`, `nav`, `main`, `label`).
- Όλα τα στοιχεία λειτουργούν με πληκτρολόγιο και έχουν ορατό focus.
- Κάθε πεδίο φόρμας έχει σαφή ετικέτα και κατανοητό μήνυμα σφάλματος.
- Σχεδιασμός πρώτα για μικρές οθόνες· έλεγχος και σε μεγαλύτερες.
- Κάθε οθόνη με δεδομένα χειρίζεται φόρτωση, σφάλμα και κενό αποτέλεσμα.
- ESLint για στατικό έλεγχο, Prettier για μορφοποίηση.
